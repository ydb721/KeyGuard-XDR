# KeyGuard XDR · v0.2.0 프로젝트 정의

## 한 줄 소개

클라우드 인증정보 이상 사용을 주제로 사건 조사·분류·모의 대응의 업무 흐름을 체험하는 XDR 기반 보안 관제 웹 시제품.

## 사용자

SOC 보안 분석가, 클라우드/백엔드 개발자, 보안 관제 업무 학습자.

## 배경

2026년 10월 Railway의 인증정보 노출 가능성 관련 침해 사고 발표를 접하고, 기존의 개인정보 노출 **사전 예방** 중심의 ShareGuard 계획에서 **사고 탐지·조사·대응** 중심으로 주제를 변경했다. 해당 사고의 정확한 침해 원인이나 'XDR 부재' 여부는 확인된 사실로 단정하지 않는다.

## 핵심 기능 세 가지

1. **이벤트 수집·탐지**: 최종 목표는 자체 테스트 API/Cloud/Endpoint 이벤트를 표준 스키마로 수집하고 탐지 규칙으로 분석하는 것이다. v0.1은 합성 이벤트만 제공한다.
2. **사고 분석**: 관련 이벤트 및 근거를 연결하고 심각도·MITRE 참조·사건 상태를 표시한다. v0.1은 샘플과 시뮬레이션 상태 변경만 제공한다.
3. **대응·재검증**: 최종 목표는 테스트 키 폐기·재발급 후 이전 키 접근 거부를 검증하는 것이다. v0.1은 모의 상태 전환만 구현한다.

## v0.1 완료 기준

- 기본 Stone+Emerald 라이트가 보이고 다크 테마 토글이 작동한다.
- Detect / Investigate / Respond & Verify 세 화면을 정상적으로 이동할 수 있다.
- 모의 사고 생성 후 KPI·사고 목록·상세 근거·감사 로그가 공통 상태로 일관되게 갱신된다.
- 초기 데이터는 v0.1.0과 동일하게 합성 사고 5건과 감사 기록 4건으로 제공한다. v0.1.1 간소화 중 4건/0건으로 줄어든 것은 의도된 범위 변경이 아니므로 복구했다.
- 사고 조사·모의 격리 시 감사 기록이 추가되며 중복 조치가 방지된다.
- 파일 다운로드 없이 외부 서버와 연결하거나 운영 API 키를 사용하는 기능이 없다.
- 테스트 환경에서 자동 스모크 테스트와 데스크톱·모바일 화면 검사를 수행한다.

## v0.2.0 구현 범위

v0.2.0의 추가 범위는 아래와 같다. 기존 v0.1 UI 완료 기준과 합성 상태 관리는 그대로 유지한다.

- 실제 로컬 HTTP 테스트 요청을 공개 교육용 토큰으로 200/401 판정한다.
- 판정에 사용하는 동일 응답 결과를 9개 필드의 이벤트로 만들고 JSONL에 저장·조회한다.
- UUID v4·UTC 타임스탬프, 직렬 저장, 재시작 영속성, 최대 5 MiB와 조회 최대 100건을 제공한다.
- 저장 장애·파일 손상·중복 ID·필수 필드 누락 시 503을 반환하고 기존 파일을 보존한다. 초기화 실패 시 UI·진단 서버는 실행하되 저장소 API는 실패한다.
- 127.0.0.1 바인딩, Host/Origin 검증, no-store, 정적 파일 허용 목록으로 localhost 교육용 범위를 유지한다.
- 실제 HTTP 통합 테스트를 별도 파일에 추가하며 기존 프론트엔드와 회귀 테스트 7개는 변경하지 않는다.

## 제외·미구현 범위

다음 항목은 현재 미구현이다.

- 운영 클라우드·Railway·GitHub 계정 연결
- 실제 API 비밀정보 조회·폐기·재발급
- EDR 센서 설치, Windows 실시간 로그 수집
- 상용 XDR 성능 또는 보안 효과 보증
- 실시간 AI 판단 모델
- 프론트엔드 API 연결(v0.4.0), 자동 탐지·상관분석(v0.3.0)
- 테스트 키 폐기·재발급과 효과 검증(v0.5.0)
- 외부 공개 서비스 인증, 다중 프로세스 저장소 공유, 자동 로그 회전·복구

## 포트폴리오 포지셔닝

v0.1은 요구사항 정의 및 UI/UX·상태 관리 구현의 증거다. v0.2.0은 로컬 HTTP 인증 결과 수집·저장·조회와 장애 처리의 증거를 추가한다. 자동 탐지 로직·실제 대응 효과의 증거로 사용하면 안 된다. 후속 버전에서 탐지와 키 폐기·재발급의 효과를 별도로 검증한다.
