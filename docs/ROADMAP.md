# 후속 개발 로드맵 · KeyGuard XDR

| 버전(예정) | 개발 목표 | 완료 판단 기준 |
|---|---|---|
| v0.1.1 | Minimal SOC UI, 다크 모드, 사건·감사 시뮬레이션 | 기존 3개 업무 화면과 회귀 테스트 7개 유지 |
| v0.2.0 | 로컬 테스트 API 및 JSONL 이벤트 수집 서버 | 실제 200·401 응답과 이벤트 일치, 영속 저장·조회·재시작·장애·5 MiB 상한 HTTP 검증 |
| v0.3.0 | 규칙 기반 탐지 API + 합성 다중 출처 상관분석 | KG-R001/R002 실제 HTTP 근거 분석, KG-R003 별도 합성 Fixture, 정상·의심 시나리오 41개 테스트 |
| v0.4.0 | SOC UI와 로컬 탐지 API 연결 | 실제/모의 출처 분리, 근거·범위·오류·비동기 경합 검증 |
| **v0.5.0 현재** | 로컬 테스트 키 폐기·재발급 + 검증 | 구 키 401·신 키 성공, 운영자 확인·감사 이력·재시작 영속성 검증 |
| v1.0.0 | 배포·보안 테스트·포트폴리오 증적 | 독립 실행 및 동일 조건 재현, 문서·실행 결과 제공 |

- 후속 버전 번호는 개발 계획이며 실제 완료를 보증하지 않는다.
- 외부 클라우드 계정과 운영 키를 사용하지 않고 자체 테스트 서버와 샌드박스를 사용한다.
- 먼저 정상 데이터 수집의 정확성을 확보한 뒤 탐지·대응으로 확장한다.
- AI 기반 분석은 규칙 기반 테스트가 충분히 검증된 뒤 선택적으로 도입한다.

v0.2.0의 `GET /api/health`, `GET /api/test/resource`, `GET /api/events`와 공개 교육용 토큰·JSONL 계약을 유지한다. Host/Origin 검증, no-store, 조회 최대 100건, JSONL 무결성 검증과 크기 상한은 동일하다. 기존 이벤트를 자동 삭제하지 않으며 저장 실패 시 503을 반환한다.

v0.3.0은 `GET /api/detections`로 검증된 전체 저장소의 이벤트 시각을 분석한다. 60초/실패 5건, 120초/실패 3건 후 성공의 의심 신호와 근거를 결정적으로 반환한다. 5분 이내 Cloud·Endpoint 상관분석은 분리된 합성 Fixture로만 검증하며 실제 수집·침해 기록으로 반환하지 않는다. 정확도나 실제 침해를 확정하지 않는다.

v0.4.0은 `detectionId`, `evidenceEventIds`, `analysisWindow`, `reason`, `synthetic` 등을 Detect/Investigate에 읽기 전용으로 연결했다. 모의 상태는 별도로 유지하고 Respond & Verify는 브라우저 시뮬레이션만 제공한다. 현재 100건 조회 제한과 범위 밖 근거 안내를 유지한다. UI의 오류·취소·출처·보안 계약은 README와 UI_SPEC에 명시한다.

v0.5.0은 공개 DEMO_TOKEN과 분리된 관리형 로컬 실습 키를 제공한다. 운영자 환경변수와 명시적 UI 확인 후에만 발급·폐기·재발급을 수행하며, 키 원문은 한 번만 응답하고 상태 파일에는 해시와 감사만 남긴다. 실제 운영 키·외부 API·자동 대응은 구현하지 않았다.
